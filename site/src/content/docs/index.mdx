## What it does

<CardGrid>
  <Card title="Jira issues" icon="list-format">
    Search with JQL, view, create, update, transition, and delete issues, and read their history.
    [Reference](/reference/jira-issues/)
  </Card>
  <Card title="Comments and mentions" icon="comment">
    List, add, edit, and delete comments, with @-mentions resolved by user lookup.
    [Reference](/reference/jira-issue-comments/)
  </Card>
  <Card title="Issue links and subtasks" icon="random">
    Relate issues to one another and inspect the link types your instance allows.
    [Reference](/reference/jira-issue-links/)
  </Card>
  <Card title="Users" icon="approve-check">
    Find users by name or account id, and confirm which account the CLI is acting as.
    [Reference](/reference/jira-users/)
  </Card>
  <Card title="Boards and sprints" icon="seti:todo">
    List boards and sprints, see what's in a sprint, and move issues into one.
    [Reference](/reference/jira-boards-sprints/)
  </Card>
  <Card title="Confluence pages" icon="document">
    Fetch, search, and list children; create, update (from storage format or Markdown), delete, and comment.
    [Reference](/reference/confluence-pages/)
  </Card>
  <Card title="Open in browser" icon="external">
    Jump from a key, id, or title to the page in your browser — or print the URL for a script.
    [Reference](/reference/open-in-browser/)
  </Card>
  <Card title="MCP server" icon="puzzle">
    The same tools for Claude, Cursor, or any MCP client, read-only unless a person opts into writes.
    [Guide](/guides/mcp-server/)
  </Card>
  <Card title="Scripts and agents" icon="setting">
    `--json` returns the raw API payload, exit codes are stable, and a read-scoped token makes writes structurally
    impossible. [Guide](/guides/scripting/)
  </Card>
</CardGrid>

## Install

```sh
npm install -g @simplysf/simply-atlassian
simply atlassian --help
```

Then point it at your instance with a few environment variables — see [Credentials](/guides/credentials/).
